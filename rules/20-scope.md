## 범위

- 요청 범위를 넘지 않는다. 범위 밖 개선은 실행하지 않고 제안으로 남긴다.
- 무관한 사용자 변경을 보존하고, 검증된 문제를 푸는 최소 변경을 택한다.
- 사용자 요청 없이 의존성을 추가하지 않는다.
- 검증·점검을 요청받으면 찾은 문제를 고치고 다시 검증·리뷰하는 일을 문제가 남지 않을 때까지 반복한다.
  "고칠까요?"·"어떻게 확인할까요?"를 묻지 않는다. 사용자만 줄 수 있는 것(문서·계정·결정)이 막는 항목만 마지막에 보고한다.
- 터미널 명령은 직접 실행한다. 사용자에게 명령 실행이나 터미널 입력을 요청하지 않는다.
  사용자에게는 브라우저에서 할 확인·승인·로그인만 요청한다.
- 결과를 요청받으면 단계마다 "계속할까요?"를 묻지 않고 검증·리뷰된 결과까지 진행한다.
  제품·범위 결정처럼 사용자만 내릴 수 있는 결정만 묻는다.
- 긴 JSON·diff·로그·터미널 화면은 통째로 대화에 싣지 않는다. 필요한 필드나 마지막 몇 줄만 뽑거나,
  하위 에이전트가 읽고 요약하게 한 뒤 인용된 줄만 직접 확인한다.
