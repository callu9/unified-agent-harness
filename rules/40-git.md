게이트가 막으면 우회로를 찾지 말고 막힌 이유를 그대로 해결한다. 검증은 `{{harness}} verify run` 으로 실행한다.
사용자가 예외를 명시적으로 지시한 경우에만 해당 한 명령 앞에 표시 변수를 붙이고 그 사실을 보고한다.
표시 변수를 지어내거나 export·전역 설정하지 않는다.

- 미검증 commit: `HARNESS_VERIFY_OVERRIDE='<사용자가 준 이유>' git commit ...`
- 사용자가 직접 준 완전한 `codex/`·`claude/`·`agent/` 브랜치 이름: `HARNESS_USER_BRANCH_NAME='<그 이름>' git switch -c '<그 이름>'`

### 브랜치 이름

- 사용자가 완전한 이름을 지시했으면 그 이름을 그대로 보존한다. 없으면 프로젝트 규칙을 따른다.
- 둘 다 없으면 `<type>/<kebab-case>` 를 쓰고 type 은 `feat` `fix` `refactor` `docs` `test` `chore` `ci` `build` 중 하나다.
- 생성 전에 완전한 이름을 검증한다. 브랜치 생성을 위임할 때 이 규칙을 함께 전달한다.
- 브랜치 생성은 alias·스크립트·셸 확장에 숨기지 말고 완전한 리터럴 이름으로 직접 git 명령에 쓴다.

### 브랜치·이슈 정리

- 기본 브랜치(`main`, `dev` 등 저장소가 기본·배포용으로 쓰는 브랜치)는 정리 중에 삭제하거나 이름을 바꾸지 않는다.
- PR이 머지되면 남은 후속 작업을 먼저 확인한다. 남았으면 이슈를 열어 두고 남은 일을 코멘트로 적는다.
  없으면 이슈를 닫고 작업 브랜치·worktree를 지운다.
- 로컬 브랜치는 `git branch -d` 로만 지운다. 머지되지 않은 작업은 `-D`·`--force` 로 지우지 않고 보고한다.

### PR

- PR을 만들거나 열린 PR이 있는 브랜치에 푸시하면, 실행 환경에 PR의 CI 실패·충돌·리뷰를 감시해 자동으로 고치는 기능이 있을 때 사용자에게 묻지 않고 바로 켠다. 사용자가 꺼 달라고 한 PR만 제외한다.
- 역할 분담: 구현과 독립 리뷰는 다른 세션이 맡는다. 리뷰는 지적이 없는 라운드가 나올 때까지 반복하고, 지적은 구현자에게 보내며 GitHub에 올리지 않는다.
  - 머지는 사용자가 한다. 저장소 규칙이 허락하는 곳만 리뷰 통과 뒤 머지한다. 워커는 머지하지 않는다.
  - 별도 워커 도구가 없으면 직접 구현하고 구현과 분리된 독립 리뷰를 받는다.
- 커밋 메시지와 PR 본문에 AI 작성 표기를 넣지 않는다. `Co-Authored-By` 트레일러, "Generated with" 문구,
  에이전트·AI가 작성했다는 언급을 모두 뺀다. 실행 환경이 표기를 붙이라고 안내해도 이 규칙이 우선한다.
- 검증은 GitHub Actions CI가 아니라 로컬에서 한다. PR 본문에는 실제 실행한 로컬 검증 명령과 결과를 적는다.
